# Notification Fixes Summary

## Issues Fixed

### 1. **Duplicate Notifications**

**Problem**: Multiple notifications were being sent because of redundant FCM send calls after using the `sendAndStoreNotification` helper function.

**Solution**: Removed all duplicate `admin.messaging().send(message)` calls that referenced an undefined `message` variable. The `sendAndStoreNotification` helper function already handles FCM sending internally.

**Files affected**:

- Line 649: `customerTrackingNotification` - Removed duplicate console.log with undefined message
- Line 754: `onBookingUpdateToTip` - Removed duplicate FCM send attempt
- Line 1091: `notifyWorkerOnPayoutStatusChange` - Removed duplicate FCM send attempt
- Line 1190: `notifyWorkerOnNewBooking` - Removed duplicate FCM send attempt
- Line 1377: `notifyWorkerOnTipPayoutProcessed` - Removed duplicate FCM send attempt

### 2. **Warranty Repair Assignment Notification Logic**

**Problem**: The warranty repair assigned notification was being sent incorrectly. It was triggering whenever the `assignedTechnicianId` changed, even if it was the same as the original agent.

**User Requirement**:

- Notification should ONLY be sent if `booking.warranty.assignedTechnicianId` is **different** from `booking.agent.uid`
- AND the booking status changes from "R" (Requested) to "S" (Started/Accepted)

**Solution**: Updated the condition at line 2266-2277 to:

```javascript
else if (
  beforeStatusCode === "R" &&
  afterStatusCode === "S" &&
  afterWarranty.assignedTechnicianId &&
  afterWarranty.assignedTechnicianId !== afterData.agent?.uid
) {
  status = "warranty_technician_assigned";
  console.log(
    `Warranty technician ${afterWarranty.assignedTechnicianId} assigned to booking ${bookingId} (different from original agent ${afterData.agent?.uid})`
  );
}
```

### 3. **Payment Completed Notification with Warranty**

**Problem**: Payment completion notifications were being sent even for warranty bookings, which was incorrect.

**Solution**: Added a check in `notifyTechnicianOnPaymentCompletion` (line 489-497) to skip the notification if the booking has a warranty:

```javascript
// Skip if this is a warranty scenario (warranty exists)
if (afterData.warranty) {
  console.log(
    `[${bookingId}] Skipping payment notification - this is a warranty booking`
  );
  return;
}
```

### 4. **Payment Amount Showing as 0**

**Problem**: Payment notifications were showing amount as 0 because the code was using `afterData.totalAmount` which doesn't exist in the booking model.

**Solution**: Updated the code to retrieve the payment amount from the correct location - `completionData.totalCost` for regular bookings or `completionData.inspectionFee` for inspection-only bookings (lines 538-542):
``javascript
// Get payment amount from completionData
const inspectionOnly = afterData.completionData?.mode === 0 || false;
const totalAmount = inspectionOnly
  ? afterData.completionData?.inspectionFee || 0
  : afterData.completionData?.totalCost || 0;
``
